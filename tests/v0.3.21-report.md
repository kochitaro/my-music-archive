# v0.3.21 検索方式切替・部分一致検索の検証記録

## 作業元と変更範囲

最新mainを取得し、PR #2のマージコミット `2a68599`（v0.3.20）から新規ブランチ `codex/v0.3.21-search-modes` を作成した。前回のマージ済みブランチは再利用していない。

本体の `index.html` と共有検索エンジン `search.js` を改修し、バージョンを0.3.21に更新した。

- 見出しと入力欄の間に「アーティスト／アルバム名」のセグメントを追加。初期選択はアーティスト。既存のセグメントの色・枠・角丸を使い、38px以上の高さとした。
- 切替時は入力を維持し、結果・候補・件数・追加表示をクリアする。自動検索せず次の検索操作を待つ。実行中の古い要求と追加メタデータ取得は既存の要求IDで無効化する。
- 検索欄のplaceholderを削除。入力欄はモードに応じた日英のaria-labelを持ち、セグメントはaria-pressedで選択状態を示す。
- アルバム名モードは最初からrelease-groupの作品名検索を実行し、アーティスト検索を行わない。複数単語は一つの引用句としてエスケープし、複合検索構文は追加しない。
- 取得した作品の中では正規化したタイトルの完全一致を優先し、その後にAPI score順。同名の別作品は残し、同じMBIDだけを重複除外する。API取得100件／表示30件と生offset管理は維持する。
- アーティストモードは作品名へ自動フォールバックしない。共有エンジンの既定autoモードには従来のフォールバックを残した。

## 部分一致

従来は正規化した名前が4文字以上、候補名の60%以上、score 90以上という条件だった。MusicBrainzが「大比良瑞希」を返していても「大比良」は3文字のため除外されていた。

今回、MusicBrainz由来の正式名・alias・ソート名・aliasのソート名に対する2文字以上の前方一致を認める。完全一致を最優先し、前方一致は候補名に対する入力の長さの比率で評価する。API scoreだけで不一致の候補を採用しない。完全一致が一つならその作品群へ進み、完全一致が複数または前方一致の候補が複数なら小さな候補一覧を表示する。選択されるまで作品取得は行わない。候補一覧には取得できた名前・識別説明・国を表示する。完全一致がなければ、一つだけ一致した前方一致候補から作品を取得する。

独自の名前辞書は追加していない。
