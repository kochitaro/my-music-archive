# v0.3.20 検索統合・検証記録

## 対象と実装

- 基点：`origin/main` の `d9149c8b9f2a310db675cfb72eee13b3fb96c97a`（v0.3.19）。取得後に作業ブランチ `codex/v0.3.20-search-integration` を作成。
- 本体HTMLを維持し、検索エンジンを `search.js` として本体と `search-test/index.html` から共有。配布時には `index.html` と同じディレクトリに `search.js` が必要。
- MusicBrainzの正式名、alias、ソート名、aliasのソート名を照合。NFKC、大小文字、空白、ひらがな／カタカナを正規化。独自のアーティスト辞書は使わない。
- 完全一致を優先。前方一致は4文字以上・候補名の60%以上・API score 90以上の場合に限定し、サーバースコアだけでは採用しない。該当するアーティストがなければ作品名検索へ移る。
- アーティスト作品は100件単位で全件取得し、MBIDで重複除外。Album → EP → Single、各分類内で発売日降順に整理してから30件ずつ表示。
- 作品名検索は関連度順のAPI結果を100件単位で必要に応じて追加取得し、30件ずつ表示。表示数とAPIの生データoffsetを分離する。
- 検索要求IDで古い結果・再試行通知を無効化。タブ変更／クリアで要求を破棄。追加メタデータ取得にも別のIDと登録先チェックを用い、別の記録作成操作を上書きしない。
- 次ページの状態は成功時だけ反映する。失敗後に同じoffsetを再取得できる。

## Unknown Artistの原因と対応

2026-10-21にMusicBrainz実APIを調査した。細野晴臣の作品browse応答は73件。`inc`なしではサンプル作品 `01fd1645-379e-4782-9fe3-de7712382d10`（Turquois）に `artist-credit` がなかった。同じ要求に `inc=artist-credits` を加えると次のクレジットを取得できた。

- credited name：`Haruomi Hosono & Yasuhiko Terada`
- nested artist name：`細野晴臣`

本体v0.3.19と旧Search Labはいずれもbrowseで `inc=artist-credits` を指定していなかった。本体は欠落した値を `Unknown Artist` に変換して登録フォームへ渡していた。

修正ではbrowseと個別release-group lookupに `inc=artist-credits` を指定。`name` を優先し、なければ `artist.name` を参照し、`joinphrase` を保持する。検索結果からListening／Collectionへ同じクレジットを引き継ぐ。クレジットが欠落する作品は追加時に個別lookupを行い、それでも取得できなければ警告と空のアーティスト入力欄を表示する。名前を入力するまで保存できず、新規検索登録の `Unknown Artist` も保存を拒否する。

既存レコードの自動補正・一括更新は行わない。

## Search Labからの継承と変更

継承：MusicBrainz由来の名前照合、かな正規化、候補評価、作品名フォールバック、100件取得／30件表示、分類と発売日順、MBID重複除外、再試行、直列化、1.25秒間隔、5分キャッシュ、実行中の同一URL重複防止、検索要求ID。

変更：

- 両画面でエンジンを共有し、Lab側のクレジット欠落も同時修正。
- score 95以上という理由だけで不一致の候補を採用する処理を削除。弱い前方一致にも条件を追加して誤検出を抑制。
- 完全一致が検索応答に含まれる場合は追加のartist lookupを省略し、アクセスを削減。
- Labの600件打ち切りを撤廃。`release-group-count` と生offsetで全件を取得し、全体順序と欠落防止を優先。
- 作品名検索の100件打ち切りを撤廃し、追加取得を実装。APIの関連度順を維持する。
- Retry-Afterの旧15秒上限を撤廃。数値指定が長い場合もサーバーの待機指示を尊重。
- 通信／応答本文の読み込みに20秒タイムアウトを追加。古い要求のfinallyが新しい要求の操作状態を書き換えないように修正。
- 本体の既存UIを保つため、Labの候補切替ボタンは本体に追加していない。Labでは引き続き候補／作品名を切替可能。

## APIエラー対策

429／502／503／504、通信例外、タイムアウトは初回を含め最大4回。待機は2／4／6秒を基本とし、数値形式のRetry-Afterが長ければその値を使う。再試行も含めて直列化し、要求開始間隔を1.25秒以上に制御する。成功結果だけをメモリに5分保持（最大180URL）。同一URLの実行中要求は共有する。再試行状況と最終エラーを画面に表示し、失敗してもキューや検索操作を復旧できる。


- 名前照合：上記4検索語の実応答fixture、かな正規化、alias sort-name、追加alias lookup、無関係な高score候補の除外、作品名フォールバックが通過。
- 705件の合成作品で600件超の取得、分類・発売日順、MBID重複除外を確認。作品名検索のoffsetとcount、実応答fixtureによるUnknown Artist再現／修正、joinphrase保持を確認。
