## 鑑賞・購入時期とリリース年

鑑賞・購入時期は月別・年別とも降順の「年月/年｜棒｜件数」。年月は8ch、年は4chを確保し、年月/年・件数ともnowrap。棒のみ可変幅。色は`#89BCCD`、背景トラックなし。

最古の有効な記録以降から現在までの間の0件を維持。月別は初期最大12ヶ月、12ヶ月ずつ追加し、開始年月で終了する。年別は従来の5年ずつ。スケールは表示中の行だけでなく、その領域の現在までの全集計対象期間の最大件数に固定し、追加するたびの伸縮を防ぐ。

日付不明は従来どおり除外、年のみの日付は年別のみ。未来の記録しかない場合は空状態。リリース年の範囲は変更せず、年別の横棒・10年ずつ追加を維持。年代別も降順の横棒へ戻し、日本語「2020年代」/英語「2020s」用に8chを確保する。

## 公演時期

月別は年プルダウン、初期は現在年。最古の有効な公演年から現在年まで全て選択可能で、0件の年も含む。各年の1〜12月を一つの縦棒に表示。対象期間内の0件は`0`、最古年の記録開始前の月と現在年の未来月は`—`とし、説明を付ける。いずれも高さ0。年月が不明な年のみの記録を1月に算入しない。最古年が年精度のみで開始月を決められない場合、その年の月別は対象期間不明として`—`とする。年単位の集計は維持。

月別スケールは選択年の最大値に合わせる。年変更は公演時期部分だけ更新し、見出しとネイティブselectを保持する。

年別は最古年から現在年まで全期間を一つのSVGに描画。表示年数上限・省略・複数段・横スクロールなし。0件の年も幅を割り当てる。棒上の件数は表示しない。共通スケール・水平補助線・件数軸。上部に対象期間を表示。

年ラベルは1年あたりの描画幅から必要な間隔を算出し、1/2/5/10/20年等の間隔で4桁表示。約48px以上の間隔を確保する。30〜55年の狭い画面では10年等の間隔になる。表示を間引くのは文字だけ。

個別年は棒の高さに関係なく、グラフ全体の該当する年の列をタップして選択する。0件の年も選択可能。選択列の薄い背景と棒の色で位置を示し、固定高さの詳細欄に年・正確な件数を表示する。細い列の操作を補う全年度のプルダウンも提供。SVGはsliderとしてラベル・最小/最大/現在値・年と件数の読み上げを設定し、左右/上下キーとHome/Endに対応。詳細変更はグラフを再生成しない。

## スコアランキングとスクロール

初期順を「アーティスト、スコアランキング、ジャンル、タグ、レーベル、鑑賞時期、リリース年」とする。Collectionは8項目（購入店舗・フォーマットを含む）、Liveは3項目で従来順。概要カードは対象外。

ランキングの集計、同点同順位、記録単位、未評価除外/0.0有効、15件ずつ追加、画像優先順位は初回PRを維持。文字色はランキング内だけ通常の白系`#e4eaf0`に統一。アーカイブ・詳細・入力の既存スコア配色は変更しない。

**確認できたコード上の問題**：旧コードは年変更・方式切替・追加/折りたたみのたびに`container.replaceChildren()`でInsights全体を削除し再生成していた。年選択と見出しを含むDOMの同一性が失われることを前版との実行比較で確認。

**修正**：変更した統計項目だけを生成・反映する。他の項目、対象の見出し、スコアのネイティブselectを保持し、フォーカスはスクロールを起こさず戻す。更新前後の項目位置からスクロールを補正。件数が減ってページ末尾に到達する場合は、その画面に必要な最小高さを一時的に確保して強制的な上方移動を防ぐ。全体を開き直すとこの高さは解除する。操作時点で見出しが画面外にある追加/折りたたみでは、見出しを画面内へ戻す。CSSの自動scroll anchoringと明示補正の干渉も防ぐ。

**検証の限界**：運営者が見たSafariの年変更時の移動そのものはChromiumでは再現しなかった。前版も合成データで年変更前後の見出し位置は同じだった。一方で前版は見出し・アーティストのDOMを両方破棄し、今回版は両方保持することを測定した。[前後の座標・DOM比較](scroll-comparison.json)。Safariでの直接原因を断定せず、実機で修正効果を再確認する。

## 統計表示設定と保存の安全性

タイトル右端にスライダー型の44pxアイコン。読み上げ名は「表示設定 / Display Settings」。外部ライブラリなし。タイトル行・概要カードは並べ替え対象の外にある。

設定画面では全項目をチェックボックス＋名称＋44pxの上下ボタンで並べ替える。非表示項目も任意の位置へ移動・再表示可能。全非表示、初期設定へ戻す、キャンセル、完了を用意。ドラッグは採用しない。iPhoneの縦スクロールとの競合を避け、上下ボタンならタップ・キーボード・読み上げで同じ操作ができるため。モーダルはEscape・Tab循環・終了後のフォーカス復帰に対応。

既存`archive-store.js`の`setSetting()`は、`prepare(current.data, settings)`から`publish()`を呼び、archive/photos/settings/metaを同じ検証付き保存境界で扱う。新しい設定をこれに追加すると記録全体の再保存や既存settings検証への変更が必要となるため、今回の要件に従い使用しない。

独立したlocalStorageキーを使用：

- `mla-insights-layout-v1:listening`
- `mla-insights-layout-v1:collection`
- `mla-insights-layout-v1:live`

保存値は`{version:1,items:[{id,visible},...]}`。項目IDは言語非依存。既存の`mma-*`設定キーと競合しない。記録ストア・写真・保存世代・既存settingsは一切書き換えない。既存保存保護への新しい例外や迂回は追加しない。

破損/欠損/型不正は初期状態へフォールバック。不明/廃止IDは無視し、重複は先頭を採用。既知のIDの順序と表示状態を保持し、新しいIDは末尾へ表示状態で追加する。全項目非表示の場合も概要とアイコンは残る。

保存失敗はこのセッションだけの設定として適用し、保存できなかった案内を出す。再読み込み後は最後に成功した設定へ戻る。音楽記録の保存状態は変えない。localStorageの読み出しに失敗した場合は初期設定を表示する。

別タブは領域別のstorageイベントで同期。別領域の編集は競合しない。同じ領域の設定画面を開いている間に別タブが保存した場合、完了を無効にしてキャンセル・開き直しを案内する。同時保存はブラウザの同期的なキー書込順（最後の成功書込）となる。未反映のドラフトを黙って上書きしない。

JSON復元ではこのキー群は変更せず、そのブラウザの設定を維持する。JSONバックアップには含めず形式変更なし。別ブラウザ/端末にJSONを復元した場合は、そのブラウザに既存設定がなければ初期状態。実ブラウザプロセスを閉じて同じプロファイルで再起動し保持を確認した。

## 暫定判断・残存課題とiPhone確認項目

1. レコード型の太さ・中心ラベルの存在感、ミュート色と同心円の見え方、微小項目と凡例を実データで確認。
2. 月別12件ずつ追加、開始月で終了、40年の過去月を参照する際の操作量と固定スケールを確認。古い記録が極端に多い場合、最近の棒が短くなるのは固定スケールの性質。
3. Live月別の現在年初期値、最古年/未来月の`—`、0件の年、月最大値ごとのスケールを評価。
4. 30〜55年の年別の俯瞰、ラベル間隔、0件年タップ、プルダウン補助、VoiceOver・外部キーボードを確認。年数が多いほど列のタップは細くなるため補助選択を推奨。
5. スコアを多数年→少数年→全期間、方式切替、追加/折りたたみして、見出し・selectが見える位置を維持するかSafariで再評価。全項目非表示/スコアだけ表示の場合も確認。
6. 設定の上下44px操作、長い英語項目名、スクロール・フォーカス、全非表示からの復帰、再読み込み/ブラウザ再起動・別タブ競合を確認。
7. 設定はブラウザ単位でJSONには含めない。端末間での設定移行は今回の対象外。

本実装の暫定仕様は運営者の再評価後に調整する。承認前のmainマージ・Production反映は行わない。
