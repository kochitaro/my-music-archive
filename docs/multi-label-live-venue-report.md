## 実装

Listening／Collectionのlabel文字列は、半角・全角カンマで分割し、前後空白・空要素を除去、大文字小文字を区別せず重複排除する。先に入力した表記と順序を保持する。

- 入力欄は既存のまま。編集されたlabelのみ `A, B` 形式に保存する。
- 読み込み時の変換や一括移行はしない。未編集のnull・未定義・空白・重複を含む既存値も保持する。
- 詳細・リストは個別値を登録順にカンマで表示する。
- 個別レーベルのフィルター、未設定、他条件とのAND、レコード単位の重複排除に対応する。
- 並べ替えは最初のレーベルで比較し、既存の方向指定処理と未設定後置を維持する（既存UIのレーベル選択肢は昇順）。
- 履歴候補も個別値に分割し、最後のカンマ以降で検索する。確定済みの前方の入力を保持して候補を追加し、入力済み候補は除外する。
- Insightsは各レーベルにレコード当たり1件を計上する。割合の分母はレーベル延べ件数。円グラフ上位10件＋その他、ランキングの追加表示は既存処理を使用する。
- Insights JSの参照クエリーを更新し、旧キャッシュの利用を防ぐ。

Live新規／編集の会場欄は同じ既存サジェスト処理を使用する。保存済みdb.liveだけから、空白除去・大小文字を区別しない頻度集計を行い、頻度降順・同頻度は名称順に表示する。表示表記は最初に見つかった保存表記（前後空白を除く）。会場マスターや外部APIは追加していない。

会場は単一値として候補で置換し、自由入力も可能。初期5件、すべて見る／閉じる、部分一致、日英見出し、IME中の選択・展開抑止に対応。会場欄とレーベル欄は16pxを指定する。既存のスクロール可能なモーダルと候補一覧を利用する。候補を選んでも保存処理は実行しない。

## データ保護・変更範囲

DB version 3、`my-music-archive-pilot-v03`、label文字列、venue文字列を維持する。保存・競合検出・読み込み失敗保護・JSON/CSV処理は変更していない。既存のsaveDB成功後にのみDBを確定する。保存失敗時は既存の「入力に戻る」から入力を保ったまま再試行できる。

MusicBrainz検索、アーティスト／アルバム検索、スコア、Live出演者／写真、トップ画面UIの実装は変更していない。サジェスト表示・展開・選択だけではレコードDB書き込みがないことを試験した。

## UI証跡

同ディレクトリのPNGは日英それぞれ、320／375／390／430／1280pxで取得。

- `labels-{listening|collection}-{ja|en}-{width}.png`: レーベル追加後と既存入力の保持
- `create-{ja|en}-{width}.png`: Live新規の履歴候補
- `edit-{ja|en}-{width}.png`: Live編集の候補選択後

横はみ出しを自動検査し、320pxの会場モーダルとレーベル入力の画像を目視確認。キーボードは表示していない。

## 保存互換性

既存の生labelを含むversion 3データで、初期読み込み・未編集保存・キャンセル時の値／プロパティ有無を比較。JSONダウンロードと復元後のDBは元データと同値。CSVをCSVパーサーで読み直して、カンマを含む生label文字列が同値であることを確認。候補選択・展開中はDB値と書き込み回数が不変。保存失敗時は元DBと入力が保持され、復帰後の保存でのみ更新される。

## 既知の制約・未検証事項

- 固有名にカンマを含むレーベルは区切りとして解釈される。この方式では単一の固有名として保持・絞り込みできない。
- **iPhone Safari実機は未検証**。実機でのソフトウェアキーボードによる遮蔽、自動拡大、慣性スクロール、実際の日本語IME変換確定中のタップは判定前に確認が必要。Chromiumのタッチ設定・16px検査・合成compositionイベントは代替実機試験ではない。
- 実機ストレージ容量枯渇は未検証。保存例外は注入試験。
- 検索の自動試験は人工API応答。MusicBrainzへの実通信は今回の検証対象外。
