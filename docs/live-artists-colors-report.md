# Live複数出演者・満足度カラー 検証報告

## 基準と範囲

作業開始時にfetchしたmain HEADは `ec2f39ca642a16ab3fa8eac4ab150759597efa0a`、正式版表記は0.3.22。専用ブランチ `feat/live-artists-heart-colors` をそこから作成。未マージPRは#6・#7（両方open）のみ。PR #8はmerged。#6・#7のブランチ・状態は変更しない。バージョン更新、マージ、公開反映は行わない。

## 実装・保存スキーマ

- Liveに任意の `artists: string[]` を追加。1公演1レコード、満足度・日付・会場・写真・メモは従来どおり共通。外部検索なし。
- 登録・編集フォームは独立した出演者欄を初期1つ表示。「＋ 出演者を追加 / ＋ Add Artist」で縦に追加し、個別削除できる。最後の欄を削除すると空欄1つを表示。追加後は新欄へフォーカス。日英対応、入力文字16px、削除ボタン44px以上。
- 保存時に出演者名の前後空白を除去し、空欄を除く。入力順・同名入力を保持し、カンマ等で分割しない。全削除は `[]`。
- 既存の `title` と「Artist / Event Title / アーティスト／公演名」欄は互換性のため保持。出演者欄と独立し、旧タイトルの意味を推測しない。出演者未設定の旧記録を開いて保存しても `artists` を自動追加しない。起動時の書き換え・移行なし。
- 詳細画面は出演者があるときだけ一覧を追加。文字列はtextContentで描画。グリッド・リストは従来のタイトル・会場の構成を維持。既存のLiveの並べ替えはtitle基準のまま。Liveに出演者検索・絞り込みを追加しない。アルバム検索は無変更。
- 保存キー、DB version=3、既存フィールド、ratingの0–10保存値／5点表示と丸め規則は維持。JSONは配列をそのまま書き出し・復元。CSVは従来形式のままで出演者配列は追加しない（全データバックアップにはJSONを使用）。
- Liveの色は共通 `liveRatingColor` に集約。表示値4.5未満は `#F07870`、4.5以上は `#E9BC64`。入力・編集・グリッド・リスト・詳細で統一。未評価は塗りなし／従来表示。0.1操作、部分塗り、ポインター・キーボード操作、クリアを維持。
- Listening／Collectionの星と `ratingColor` は変更なし。4.3以上の `#E08AA1`、通常の `#e9bc78` を維持。色によるデータ移行なし。

## データ保全

出演者は保存までフォーム内だけで編集し、新しい配列を保存候補へ設定。既存レコード／配列を直接変更しない。候補DBの分離、localStorage書き込み成功後の確定、失敗時の元DB保持を維持。`migrate` / `saveDB` / `saveRecord` / `ratingColor` はmainと文字列一致。読み込み失敗時のガード、写真削除、記録削除、JSON復元は既存処理を維持。
