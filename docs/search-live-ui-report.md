## 基準と作業範囲

- 開始時main：`4a302231dcfd66e57af4dcf13123ffd663fc47de`、正式版v0.3.22。

## 実装した5件

1. アルバム名検索：既存searchNorm（NFKC・大小文字・かな・空白・引用符の正規化）で完全一致、部分一致、その他の順。同じグループは発売日降順、日付なしは末尾。MusicBrainzスコアを日付より優先しない。追加読み込み時に取得済み全件を重複排除して再整列。Search Labも同じ処理を利用。
2. 両検索モードの発売日直近にprimary-typeのAlbum／EP／Singleを既存の補足情報と同じ文字で表示。他の分類・欠落は非表示。追加ボタンとメタデータ継承は維持。
3. Live追加リンク：`＋ ライブを追加`／`＋ Add Live`。Listening／Collectionと同じクラスで淡いシアン、背景・枠線・下線なし、最低44px。既存の登録ダイアログを開く。
4. Liveの新規・編集・詳細・一覧・読み上げ名・並べ替え・入力検証メッセージを満足度／Satisfactionへ変更。Listening／Collectionは評価／Ratingを維持。
5. Liveのみ5個のピンク（#E08AA1）のハートへ変更。共通SVG関数の任意引数で形状を切替。既存の部分塗り、キーボード・ポインター、未評価、0–10保存値と5点表示を維持。Listening／Collectionの星と色分けは維持。

## 制約・未確認事項

- 保証するのは取得済み全件の整列。MusicBrainzは100件単位の既存APIページ、UIは30件ずつ表示。未取得ページの完全一致・新しい作品は、読み込み後に先頭等へ移動し得る。サーバー側の検索件数上限・インデックス・順位のため、MusicBrainz全件での完全な順序／網羅性は保証できない。全件整列目的の追加API呼び出しは行っていない。
- 未分類・Otherは分類文字を表示しない。APIが返すタイトルに検索語を含まない場合は完全／部分一致の後へ配置する。
- iPhone Safari実機、VoiceOver、実APIの最新応答・全件網羅性は未確認。Chromiumのモバイル設定は実機検証の代替ではない。
- Liveの未評価は既存と同じ表示（入力は空の5個、一覧はアイコンなし、詳細は「—」）。内部値8.5の表示丸め等も既存のまま。
