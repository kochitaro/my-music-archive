## 改修前後と保全方法

| 対象 | 改修前 | 改修後 |
| --- | --- | --- |
| DP-01 | メモリから削除してから保存。失敗するとメモリ側の削除が残り、後続保存で確定する | 対象領域の候補配列を作成し、書き込み成功後だけDBを差し替える。失敗時は元の参照・全項目・順序を維持 |
| DP-06 | レコードへ変更を適用後に保存。Object.assignによる巻き戻しでは、新たに追加したプロパティが残る | 元レコードを変更せず置換候補を作成。メモ・写真・任意項目の有無を含め、失敗時には元レコードを維持 |
| 写真削除 | 直接変更後に値だけ巻き戻す | 写真削除も候補保存を使用。元にphotoプロパティがない場合も失敗時には追加しない |
| DP-02 | 読み込み失敗後も空DBで動作・保存可能 | 読み込み失敗状態を保持。操作入口と共通saveDBで保存を停止。一覧は0件表示にせず停止理由を表示 |
| 回収・バックアップ | 読み込み失敗後の空DBを通常バックアップとして出力可能 | 通常JSON/CSV出力とJSON復元を停止。取得済み元文字列のみ、解析・整形・移行せず.txtで回収。取得できなければ回収不能と表示 |

新規登録・通常JSON復元も共通保存の候補方式に合わせた。正常な既存の旧形式読み込みは維持し、現行キーが存在して読み込みに失敗した場合には旧キーへ切り替えない。空文字列の現行キーも解析失敗として扱う。旧キーからの正常移行時に新キーの書き込みが失敗した場合も、保守的に保存停止にする。

保存失敗通知は「保存できず、変更は反映されていない」ことと再試行・キャンセルを案内する。編集フォームの未保存入力は残すが、保存済みDBとは分離する。原因不明の読み込み失敗を「破損」と断定しない。初期化・消去・復旧機能は追加しない。

## iPhone Safari実機検証手順（未実施）

検証対象コミットを別ディレクトリにcheckoutし、ローカルHTTPサーバーで配信する。公開サイトには反映しない。iPhoneから専用テスト用オリジンを開き、合成データだけを用いる。Mac Safariの開発メニューでiPhoneのページに接続する。既存の利用者データがあるオリジンでは以下の操作を実施しない。端末/iOS/Safariバージョン、コミット、結果を記録する。

1. 通常系: 3領域に2件ずつ、異なるID・日付・評価・タグ・メモ・写真を登録。JSONを保存する。編集/写真置換/写真削除/記録削除、JSON復元、再読込を実施する。期待: 各操作が保存され、復元後のID・主要項目・写真・順序がバックアップと一致する。
2. 欠落項目: 上記JSONのコピーから任意項目（memo/photo/tags/genre/label、Collectionのstore/format/price/condition、Liveのvenue/rating等）を削除した合成JSONも用意し、正常起動中に復元する。
3. 書き込み例外: 開発コンソールで次を実行する（ページ再読込で解除される）。

   ```js
   window.testOriginalSet = Storage.prototype.setItem;
   Storage.prototype.setItem = function (key, value) {
     if (key === 'my-music-archive-pilot-v03') {
       throw new DOMException('Synthetic quota failure', 'QuotaExceededError');
     }
     return window.testOriginalSet.call(this, key, value);
   };
   ```

   3領域で削除・メモ編集・写真置換・写真削除を試す。期待: 失敗通知、編集画面が残り再試行/キャンセル可能。キャンセル後の一覧/詳細とJSONが操作前に一致し、欠落プロパティが新設されない。`Storage.prototype.setItem = window.testOriginalSet` で解除し、別領域を保存して再読込しても失敗した操作が混入しない。同じ操作の再試行成功も確認する。
4. 起動時解析失敗: 専用オリジンで正常な合成DBの元文字列をファイルへ控え、現行キーに `'{invalid\r\n日本語'` または `'{"unsupported":true}'` を保存して再読込する。空文字列も試す。期待: 「読み込めなかったため上書き防止で保存停止」「新しい記録を保存できない」が表示され、正常0件のように見えない。登録/編集/削除/通常バックアップ/復元が停止し、タブ/表示形式/言語変更・再読込後も停止が継続する。既存旧キーがあっても切替・上書きしない。
5. 元データ回収: 「読み込みできなかった保存データを回収」を押し、Safariから「ファイル」に保存する。期待: 通常バックアップと区別され、内容が元文字列に完全一致（整形なし、改行/日本語も保持）。キーの値は変わらない。
6. 読み取り例外: 起動前から `Storage.prototype.getItem` が現行キーで `SecurityError` を投げるテスト用ローカル文書を別途用意し、iPhoneで開く（ページ起動後に注入して再読込すると注入は消えるため不可）。期待: 保存停止、回収不能の明記、空データの代替出力なし。全getItemで例外となる条件でも案内を表示する。元キーの確認は例外を外したテスト用文書で行う。
7. 実容量不足: 端末の通常データを圧迫せず、専用オリジン内の合成データだけでlocalStorage上限に到達させ、メモ・写真の増加を伴う保存が実際に失敗する条件を作る。期待: 元DB/画面/JSONが保全され、テスト用容量を解放した後の別領域保存にも失敗変更が混入しない。例外注入結果とは別に記録する。削除保存の失敗は容量上限だけでは再現しない場合があり、注入試験と混同しない。
