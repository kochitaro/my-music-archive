## 保存境界・起動異常

`migrate`は形式判定、元構造・型・ID検証、旧配列移行、移行後検証とJSONコピーを担当する。元のオブジェクトや配列を変更しない。既知領域ごとに既知項目を検証し、別領域でのみ既知の名前は未知プロパティとして保持する。

`commitDB(candidate)`を共通の同期保存境界とした。候補を検証・コピーし、localStorageへの書込が成功してから`db`を確定する。通常保存は`saveDB`が既存のDP-02停止ガードと失敗表示を付けて呼び出す。旧キーからの起動時移行も`commitDB`を使う。保存失敗時に候補を採用しない。保存後に旧rawを書き戻す処理はない。

起動時に読込・構文・構造・型・ID・移行保存の異常があれば正常DBとして採用せず、既存DP-02の停止パネルを使う。空DBによる上書き、旧キー削除、フォールバック、自動修復を行わない。取得済みrawを無加工の回収ファイルにする。rawを取得できない場合は回収不能と表示する。エラー位置は領域・1始まりの記録番号・項目名で示す。内部例外文字列は復元画面に出さない。

## 互換性

対応形式は正式旧Listening配列と、versionが数値3かつlistening／collection／liveがすべて配列のオブジェクト。versionなし・1・2・未知versionのオブジェクト、null、異常レコード、欠落領域、ID欠落／誤型／領域内重複は拒否する。

- 手動作品の空MusicBrainz ID、同じ作品の複数記録、領域をまたぐ同一entryIdを許可。
- tagsの文字列・配列・null・欠落、配列内の空白・重複を無加工で保持。
- 任意項目の欠落・空文字・null、写真、Collectionの購入文字列／数値、旧日付文字列を保持。既知項目の誤型・解釈不能日付・ISO年月日の存在しない日付は拒否する。購入値を数値へ強制変換しない。
- Live artistsは欠落・空配列・文字列配列を許可。順序・重複を保持。nullや文字列単体などの誤型は拒否。
- 現行ratingは数値／数値文字列0〜10、および空文字・null・欠落をそのまま保持。8.5や8.55も許可し、表示刻みを理由に丸めない。非数値・範囲外は拒否。
- 旧配列だけは確認済み1〜5のratingを2倍した文字列に移行。未評価の空文字・null・欠落は保持。欠落／空のentryIdのみ生成。非空IDは空白を含めてそのまま保持し、自動再割当てしない。旧listenedからdateへの対応はdateプロパティ欠落時のみ行う。
- version 3ルートとレコードの未知JSON値は保持。JSON.parse／オブジェクトspreadによって`__proto__`・`constructor`をデータとして扱い、prototype setter経由のコピーはしない。未知項目においても非有限数値はnullへ無通知変換せず拒否。

意図的な変更は不正形式の全体拒否、通知付き操作停止、正式移行以外のID補完廃止、未知ルート項目の保持、復元取消の明示、保存後の描画失敗の別通知。スコアUI操作自体の既存仕様は変更していない。

## PR-Bへの引き継ぎ

`commitDB`の「候補検証→永続書込→db確定」が保存境界。PR-BではWeb Locksの中で保存元rawの照合とこの処理を実行する設計にできる。ロック取得後に再度検証し、保存済みrawの基準更新は書込成功後に行う必要がある。PR-Aはraw照合やロックを行っていない。

非同期化が必要なのは`commitDB`／`saveDB`／`saveRecord`および呼び出す起動時旧キー移行、Listening・Collectionの保存、新規Live保存、編集、削除、写真除去、JSON復元。既存asyncハンドラも現在は同期のboolを受け取るためawait対応が必要。ロック待機中の候補・編集対象の変化も再確認すること。storageイベント通知と未保存入力回収はPR-Bの範囲。

PR-Aの一意性再確認は同じタブの対象を保護するもので、他タブからの上書きを防止しない。同一ブラウザの別タブ・別窓で最終書込が勝つ競合リスクは残る。β公開可とは判定しない。

mainへの直接コミット、自己マージ、正式環境へのデプロイは実施しない。①によるレビュー待ちとする。
