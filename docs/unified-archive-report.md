# MLA IndexedDB保存統一：実装・検証報告

2026-11-21 UTC。基準main：`fdbefae6f92bdb71d3008047d1949523940e47ec`。
専用ブランチ：`feat/indexeddb-archive-unification`。PR作成までの承認に基づく作業。mainの変更・マージ・正式環境への反映は行っていない。利用者の実データ、正式サイト、既存ブラウザプロファイルにはアクセスしていない。

## 変更した動作

Listening・Collection・Liveの記録、写真、言語・一覧表示設定を `mla-archive-v1` に統一した。新アプリはlocalStorageへの通常保存を行わない。

| ストア | 内容 |
|---|---|
| `archive` | 写真IDを参照する3領域の記録スナップショット。順序・未知のフィールドも保持 |
| `photos` | SHA-256をキーとする変更不可の写真文字列 |
| `settings` | 言語とアーカイブ別一覧表示設定 |
| `meta` | schema、generation、pending/ready、内容のdigest、旧保存元の指紋、設定世代 |

`archive`・`settings`・`meta` の `current` が現行候補。通常保存時は直前の検証済み内容を `previous` にも保持する。記録・写真・設定・世代・previousへの退避を同一readwriteトランザクションで確定する。

写真変換・ハッシュ計算はトランザクション開始前に行う。既存写真のコピーは再圧縮せず、data URL文字列をそのまま保存する。新規選択画像の900px/JPEG変換は従来どおり。

## 保存・移行の確定境界

1. 起動中は画面をinertにして通常操作を禁止する。
2. 旧版と共通の `mla:my-music-archive-pilot-v03:write` Web Lockを取得する。
3. 新DBがあればその状態を検証する。新DBが存在せず旧保存元を正常に読めた場合に限り自動移行する。
4. 記録、必要な写真、設定、`pending` メタデータを一括確定する。
5. DBの一つの読み取りトランザクションから記録・設定・全参照写真を取得し、写真のSHA-256と内容全体のdigestを照合する。
6. 保存元の指紋・世代が同じであることを確認し、別トランザクションで `ready` を確定する。
7. `ready` の確定完了後にのみ通常保存を許可する。

- 確定前の取消・例外では全ストアの変更が取り消される。
- `pending` 確定後の中断は次回起動で読み戻し・照合を再実行する。単にフラグだけをreadyへ変更しない。
- 新旧分岐、読取例外、構造不正、写真欠落・破損、照合不一致では保存を停止する。空アーカイブを生成して原本へ上書きしない。
- 通常保存の確定後に照合できなくなった場合も、直前の検証済み記録・設定と写真は保持される。自動巻き戻しは行わない。
- 既存localStorage、旧写真DB、旧整理ジャーナルを削除しない。旧モジュールには読取専用モードを追加し、移行時に未作成の旧DBを新設することも避ける。
- 写真GC・旧キー整理の新しい呼び出し経路は追加していない。

### 移行元

旧写真ID形式 → 旧v03 → 旧v1配列の優先順位を維持する。旧v1の鑑賞日・評価尺度・内部ID補完も維持し、自動移行時の補完IDは再実行しても一致する。

既存の分岐判定・整理ジャーナルを確認する。別内容の残存旧キーは保持し、自動結合しない。新DBへ移行後に旧側が変わった場合も、原本指紋の変化で停止する。

言語・表示設定も旧キーから移行する。壊れたJSONや不正な設定は無言で既定値に置き換えず、移行を停止して原本を保持する。正常時の既定値・表示項目・順序は維持する。

## 競合・入力保持・回収

Web Lockに加え、IDBトランザクション内で期待世代を比較する。BroadcastChannelは早期通知に使い、通知を逃しても世代比較で上書きを拒否する。focus/pageshow時にも照合し、旧localStorageのstorageイベントも監視する。

保存処理中の操作制限、フォーム・Fileの保持、失敗後の再試行、未保存入力の破棄確認を維持した。写真保存失敗時の「キャンセルして入力へ戻る／今回選んだ写真なしで保存する」の明示選択も維持する。保存後のフォーム照合は、IDBでのプロパティ順序差を内容変更と誤認しないよう正規化比較にした。

異常時の既存JSON操作から、次の保存元を個別に書き出せる。

- 0：統一DBの現行候補
- 1：旧写真ID形式
- 2：旧v03
- 3：旧v1
- 4：直前の検証済み保存（存在する場合）

分岐復旧は、現在存在する新旧の全分岐JSONを退避・ファイルから読み戻し照合し、採用内容を明示した場合だけ実行する。旧側の変更によってpending状態で止まったケースも、この手順で復旧できる。

原本回収は `mla-unified-recovery` 形式で、旧キーの生文字列・回収可能な旧写真、新DBの全ストア・current/previous・写真を読み取り専用で出力する。未知のDBバージョンでも可能な範囲で生データを回収する。これは通常バックアップではなく、通常JSON復元としては受け付けない。

## バックアップ・既存機能への影響

通常JSONは写真本体を含むversion 3のまま。内部の写真ID・保存世代・移行状態は通常JSONに混入させない。旧v03・旧v1入力経路も維持する。言語・一覧設定は従来の通常JSONに含まれていないため、形式互換を優先し今回も追加しない。

CSVの列・値変換、ArchiveとInsightsの表示ロジック、検索ロジック、CSSは変更していない。起動・保存・設定保存は非同期となり、移行・読取失敗時は操作を止める。設定保存に失敗した場合は既存の表示失敗通知または言語保存失敗通知を出す。

## 残存リスク・未検証

- **実容量不足、OSによる強制終了・電源断は未検証。** QuotaExceededError注入、トランザクション取消、ページ終了の成功を代替合格とはしない。
- **iPhone/iPad Safari実機は未検証。** Linux WebKitの成功をSafari実機の合格とは扱わない。
- 旧原本、直前の検証済みスナップショット、古い写真を保持するため、移行時・継続利用時の容量余裕が必要。写真GCは未実装。
- 全件スナップショット・全写真照合を維持しており、大量の独立写真での起動時間・ピークメモリ・長期運用の性能は未検証。
- IndexedDBとlocalStorageをまたぐ原子的トランザクションは存在しない。同じWeb Lockに従わない旧版を完全に排他できず、原本再照合・分岐停止で保護する。公開時には旧版タブを閉じる。
- ブラウザによるストレージ消去・端末故障に対する永続保証はない。新DBだけが消去され旧localStorageだけが残った状態は初回移行と区別できず、残存旧原本からの移行候補となる。旧原本は移行後の編集を含まないため、最新の外部JSONバックアップを保持する必要がある。
- 保存確定後、成功通知前に中断した操作は、再起動後の照合で保存済みとして確定する場合がある。自動的に旧内容へ戻さず、currentとpreviousの退避経路を用意した。
- 正常JSONにできない破損分岐は生データ回収と隔離先での復旧が必要。同一ブラウザ内での自動修復・自動統合はしない。
