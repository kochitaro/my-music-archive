## Collectionの既存スコア仕様と実装

事前調査：購入記録はそれぞれの`rating`に0〜10の値または未設定を保持する。編集処理は既存`validateRating()`を通して、その購入記録へ保存する。`rate(record)`は空文字/null/未定義を未評価として区別し、数値0を有効値として返す。表示は既存`fiveScore(raw)`（`Math.round((Number(raw)/2)*10)/10`）で0.0〜5.0に換算する。例：0→0.0、8.6→4.3、10→5.0。

Insightsには既に全領域共通で`db[section]`と`rate`/`fiveScore`/`ratingReadout`/`art`が渡されている。今回、Collectionもこの既存呼出しと共通ランキングを使う。Listeningとの参照・関連付け・スコアのコピー・独自算出は一切追加しない。専用試験ではListeningとCollectionに異なる評価を与え、Collectionの結果だけを独立した期待値と照合した。

仕様：

- スコア設定済みの購入記録のみ。0.0は含め、未評価は除外。
- 表示する5点スコアの降順。同点は1,1,3方式。安定ソートにより同点の元配列順を維持。
- 記録単位。同一作品の複数購入も別行。重複排除・平均なし。
- 初期はリリース年・すべての年。購入年（date）/リリース年（release）の方式切替と年プルダウンを持つ。
- 選択肢はスコア対象記録に存在する有効年のみ、降順。日付不明は全期間には含み、年指定では除外。
- 方式変更時は、選択年がその方式にも存在すれば維持し、存在しなければ全期間へ戻す。年/方式変更時は15件に戻す。
- 初期15件、15件ずつ追加、既存の折りたたみ。年選択に可視説明ラベルを付けず、読み上げ用「対象年 / Year」を維持。
- 「購入年 / Purchase Year」「リリース年 / Release Year」「スコアランキング / Score Ranking」。

順位｜ジャケット｜作品情報｜白系スコアの共通描画を使用するため、サイズ・余白・文字・線はListeningと同じ。ユーザー写真優先、CAA全体表示、画像なし/失敗時の音符は既存`art`のまま。取得・保存方式を変えていない。アーカイブ・詳細・入力のスコア色は変更しない。

年変更・方式変更・追加・折りたたみは既存の項目単位更新を利用。統計全体や他項目を再生成せず、見出しとネイティブselectを保持し、位置補正とフォーカス復帰を行う。

## 表示設定の移行

初期順は「アーティスト、スコアランキング、ジャンル、タグ、レーベル、購入店舗、フォーマット、購入時期、リリース年」の9項目。概要カードは対象外。従来の8項目を欠落させない。

- 未保存：scoreを2番目に表示。
- 保存済み：8項目の順序・表示状態を保持し、新しいscoreを末尾に表示状態で追加。
- 初期化：scoreを2番目に戻し、全項目表示。

既存の`mla-insights-layout-v1:collection`をそのまま使用し、キー・形式・バージョンを増やさない。任意の移動/非表示/再表示・再読み込み後の保持を確認。設定変更前後でIndexedDBのarchive/photos/settings/meta全キー・値が完全一致した。既存の保存失敗・別タブ・破損設定・ブラウザ再起動の試験も維持。

JSON復元後もそのブラウザの表示設定は保持する。JSONに属性を追加せず、他端末へ表示設定を移す仕様にはしない。

## Liveの表示順

公演名→会場→年月日へ変更。公演名は既存の主表示、会場と日付は既存の12px・控えめな色を維持する。未登録/空白の会場や日付は要素自体を作らず、「会場未設定」「日付不明」の行も表示しない。両方ない場合は公演名だけで空行なし。

順位・写真・スコア位置、全期間集計、追加表示、表示設定は変更なし。長い公演名/会場の既存2行省略も維持。
