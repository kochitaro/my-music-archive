## 原因と修正

`saveDB()` の旧成功処理は写真削除だけを例外として、その他の成功すべてでdraftを消していた。写真削除の例外も、draft未作成の場合の残存編集を検査せず、既存draftのproposedRecord.photoを無条件に空文字にしていた。draftRecoveredは入力の世代や保存対象との対応を持っていなかった。

修正は既存のパネル、JSON出力、テキスト代替をそのまま用いる。履歴リストや新しい永続化方式は追加しない。

- `formState()` / `sameForm()`：フォーム値・部分日付・出演者・選択Fileの同一性をスナップショット化。回収パネル自身のtextarea等は入力に含めず、自己埋め込みを防ぐ。
- `formOwner` / `formSession` / `draftContext`：現在の1フォームと回収対象の対応だけを保持する。別フォームへの置換を確認前に止める。
- `activeOperation`：操作開始時の入力/Fileと内部操作トークンを保持。非同期待機中の二つ目の保存を保存境界でも拒否する。`operationBusy` による既存UIガードも維持する。
- `saveDB()`：同じフォーム全体が、操作開始時から変わらず、候補どおりDBに確定した場合だけ回収状態を解消する。書込み後に入力相違を検出した場合は書戻さず、最新入力を回収可能にし、呼出元へフォーム閉鎖を許可しない結果を返す。表示も「保存した内容と残る入力が異なる」と区別する。
- 写真削除成功：開いた時点のフォーム値と現在値を比較し、残る編集を回収する。`photoState.savedPhotoRemoved` で保存済み削除を示す。選択中の未保存写真の変換結果はFileと対応する場合だけ維持する。
- `captureDraft()`：同じ対象の追加入力は最新値に更新し、回収確認を解除する。処理済み写真を別File/選択解除へ引き継がない。新写真が未変換ならphotoをnullとして回収不能を明示する。
- 登録/編集ハンドラ：commit前の変換エラーでもフォーム、選択File、入力の回収データを保持する。
- JSON復元：失敗した復元候補と**全体が同一**の再試行成功だけは、その復元の回収状態を解消できる。別内容の復元は確認前に止める。比較用JSONはメモリ内のみに保持し、回収ファイルへDB全体を混入させない。旧形式のID再生成等で候補が異なる再試行は、回収確認が必要な側へ倒す。

意図的に維持した動作：同じ入力全体を正常保存できた場合は回収ファイルを別途作らなくてもフォームを閉じられる。写真削除だけで未保存編集が存在しない場合は追加の回収確認を要求しない。既に回収確認済みの入力は明示的にフォームを開き直す操作で置き換えられる。確認後の再編集は新たな未回収状態になる。

`commitDB()` のWeb Locks、排他名、ifAvailable方式、ロック内raw照合・検証・書込み・成功後DB確定は変更していない。DB version、保存キー、通常のJSONバックアップ形式、PR-Aの検証仕様も変更していない。

## PR・差分と残存リスク

変更ファイルは `index.html`、追加単体/ブラウザ試験2ファイル、本報告、旧報告への参照追記、`docs/pr-b-review-evidence/` の証跡。追加コミットと全ファイルの正本は [PRのCommits/Files changed](https://github.com/kochitaro/my-music-archive/pull/13/files)。mainとの全差分は [compare](https://github.com/kochitaro/my-music-archive/compare/main...codex/pr-b-dp05)。

- 同じフォームの現在入力を保護する方式であり、ユーザーが変更した過去の全入力を履歴として保持するものではない。
- 回収ファイルのOSへの保存完了は検知できず、利用者の明示確認が必要。元写真バイナリは埋め込まず、未変換/選択変更後の画像は回収できない旨を示す。
- 保存後に入力が変化した特殊な境界では、DBの書込みは成功したまま、フォームを開いて残る入力を保持する。以前のDBへの自動書戻しはしない。
- 旧版タブや外部スクリプトが共通ロックを無視する競合は従来どおり保証外。
- Safari実機、実容量不足、OS強制終了、凍結・復帰は③の別工程として未実施。例外注入の成功で実機合格としない。
- main変更、PRマージ、新規PR作成、デプロイ、実利用者データ操作は行っていない。
